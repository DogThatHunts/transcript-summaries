UC berkeley's Frank Coyle on the Claude Certified Architect exam

Frank Coyle, a computer science instructor at UC Berkeley with over 30 years of teaching experience, shares his insights on preparing students for a world of agentic AI. To help developers navigate this shift, Coyle breaks down the structure and core concepts of Anthropic's Claude Certified Architect (CCA) exam, focusing on practical design patterns and critical anti-patterns.

Overview of the CCA exam

Released in March, the CCA exam is a timed, proctored, scenario-based test. While designed for companies within the Anthropic ecosystem, individuals can take it for $99 once every six months. The exam evaluates five core domains:

  • Agentic architecture (27%)
  • Claude code and workflow configuration (20%)
  • Prompt engineering and structured JSON output
  • Tool design and Model Context Protocol (MCP) integration
  • Context management and reliability

The exam draws from six production scenarios, randomly selecting four for any given test session. Coyle uses these scenarios to highlight how to build—and how not to build—agentic systems.

Key agentic design patterns and anti-patterns

Scenario 1: customer support and the stop reason loop

When building customer support agents, a common mistake is letting an agent execute tasks without monitoring its state.

  • The anti-pattern: Treating the LLM as an active execution engine. LLMs are probabilistic next-word predictors; they cannot execute tools directly. They can only output the parameters required for your local code to run them.
  • The pattern: Implement a while true loop that monitors the model's stop_reason. If the model stops because of a tool_use request, your code executes the tool, feeds the result back into the message history, and continues the loop. Developers must also monitor for stop reasons like token limit exhaustion to handle partial outputs safely, and implement human-in-the-loop escalation when confidence scores are low.

Scenario 2 & 3: multi-agent specialization and context isolation

In complex research or workflows, developers often struggle with coordinating multiple agents.

  • The anti-pattern: Creating a single "super-agent" overloaded with dozens of tools, or letting all sub-agents dump their entire thought processes and histories into a shared primary context window.
  • The pattern: Build specialized, single-purpose agents equipped with only one or two tools. To prevent "groupthink" and context bloat, isolate each agent's context. For example, when using a critic agent to evaluate a claim, pass only the claim and the evidence—do not pass the entire chain of thought that generated them. Keeping contexts small reduces token costs, improves model accuracy, and prevents agents from devolving into a single consensus.

Scenario 4 & 5: developer productivity and continuous integration

Managing long developer sessions and automated pipelines requires strict boundary control.

  • The anti-pattern: Allowing context windows to grow unbounded, or running interactive permission prompts inside automated continuous integration (CI) pipelines.
  • The pattern: Use "context forking" to run subtasks (like scanning logs for errors) in independent threads. Once complete, pass only the summarized result back to the main thread. If token counts exceed thresholds (e.g., 150,000 tokens), apply compaction or compression algorithms to shrink the history. For CI pipelines, disable interactive modes entirely. For non-urgent, high-volume tasks, leverage Anthropic's batch mode to run queries at a 50% cost reduction with a 24-hour turnaround.

Conclusion and philosophy

Coyle closes with a philosophy of active experimentation, quoting artist Sister Corita Kent: "Nothing is a mistake. There's no win and no fail. There's only make." Understanding what not to do through anti-patterns is often the fastest path to designing highly reliable, agentic systems.
