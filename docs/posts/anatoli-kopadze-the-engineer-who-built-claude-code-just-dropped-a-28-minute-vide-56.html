Boris, a member of the technical staff at Anthropic and the creator of Claude Code, presents a practical guide on leveraging the tool's agentic capabilities. Rather than focusing on line-by-line autocompletion, Claude Code is designed to build entire features, write functions, and fix bugs directly from the terminal.

What makes Claude Code different

Unlike traditional autocomplete tools, Claude Code operates as a fully agentic assistant. It integrates directly into any existing workflow, working locally over remote SSH, Tmux, and across all IDEs.

Key architectural benefits include: * No remote indexing: Codebases are not uploaded to remote databases or used to train generative models; all processing remains local. * Zero setup delay: Because there is no indexing phase, developers can begin querying their codebase immediately after installation.

Accelerating onboarding with codebase Q&A

Boris recommends that teams starting with Claude Code begin purely with codebase Q&A before attempting automated code edits. This helps engineers learn the boundaries of the model's capabilities.

At Anthropic, technical onboarding that previously took two to three weeks now takes only two to three days by having new hires query the codebase directly. Useful Q&A patterns include: * Instantiation queries: Asking how specific classes or functions are instantiated and used across the codebase. * Git history exploration: Asking Claude to inspect git logs to explain why complex functions were designed a certain way, who introduced specific arguments, and which issues they link to. * Standup preparation: Querying Claude at the end of the week to summarize everything the developer shipped based on local git logs.

Code editing and planning workflows

Claude Code uses a minimal, highly effective set of tools to edit files, run bash commands, and search directories. Boris highlights several strategies to maximize editing efficiency:

  • The planning prompt: For large features, developers should instruct Claude to brainstorm and present a plan for approval before writing any code (e.g., "Before you write code, make a plan").
  • Automated Git operations: Claude can interpret high-level commands like "commit and push" to automatically create branches, format commits based on project history, and open pull requests.
  • Feedback loops: Claude performs best when given a tool to check its work. By providing access to unit tests, Puppeteer, or simulator screenshots, Claude can iteratively self-correct until the implementation is perfect.

Managing context with CLAUDE.md

To prevent repetitive prompting, developers can feed context to Claude hierarchically using configuration files:

  • Project-level context: A CLAUDE.md file placed in the project root is automatically read at the start of every session. This should contain common bash commands, style guides, and architectural decisions.
  • Local context: A local, untracked version of CLAUDE.md can be used for personal preferences without checking it into source control.
  • Directory-specific context: Nested CLAUDE.md files in child directories are pulled into the context window only when Claude is actively working within those specific folders.
  • Enterprise policies: Organizations can define global enterprise policies to auto-approve safe commands (like test runners) or block restricted actions (like fetching specific external URLs) across all employee machines.

Terminal shortcuts and power-user features

Boris shares several built-in terminal shortcuts designed to streamline interactive sessions:

  • Shift-Tab: Switches Claude into auto-accept edits mode, bypassing the need to manually approve every file modification while still requiring approval for bash commands.
  • # (Pound sign): Instructs Claude to remember a specific rule or tool usage, automatically appending it to the active memory file.
  • ! (Exclamation mark): Drops the user directly into local bash mode. The command and its output are automatically appended to Claude's context window.
  • Escape: Safely interrupts Claude at any point without corrupting the active session.
  • Escape twice: Jumps backward in the session history.
  • Control-R: Displays the entire raw output currently held in Claude's context window.

The Claude Code SDK and pipeline integration

By using the -p flag, developers can access the Claude Code SDK, turning the assistant into a highly intelligent Unix utility. This allows engineers to pipe data in and out of Claude using standard command-line tools.

Examples of SDK pipelines include: * Piping git status or Sentry CLI logs into Claude to diagnose errors. * Processing large log files from cloud storage buckets to extract anomalies. * Outputting structured streaming JSON to feed downstream automation pipelines.

Audience Q&A

How does Claude Code handle the safety risks of executing bash commands?
Boris explains that Anthropic uses a complex, tiered permission system. Claude Code performs static analysis and read-only command detection to determine which bash commands are safe to run automatically, allowing developers to avoid constant manual approval prompts without sacrificing system security.

Does Claude Code support multimodal inputs?
Yes. Claude Code is fully multimodal. Developers can drag and drop UI mockups, copy-paste images, or provide file paths directly into the terminal. Combined with a Puppeteer MCP server, Claude can visually inspect its own web output against a design mockup to iterate on frontend code.

Why did Anthropic build a CLI tool instead of a dedicated IDE?
First, Anthropic's internal engineering team uses a highly diverse set of editors, including VS Code, Xcode, Vim, Emacs, and Zed; a terminal tool serves as the ultimate common denominator. Second, Boris notes that given the rapid pace of AI model improvements, traditional IDE interfaces may become obsolete by the end of the year, making heavy investments in custom IDE UI less practical than building robust agentic command-line tools.
